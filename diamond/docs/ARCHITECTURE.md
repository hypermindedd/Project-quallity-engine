## ۱. مسئله‌ی اصلی

تست خودکار ایرادهای «حسی» (زشتی، شلوغی، لگِ محسوس، دکمه‌ی اضافه) را خوب نمی‌گیرد و نظر بازبین انسانی که بهترین داده است، نه ثبت می‌شود و نه به کد وصل می‌شود. Diamond نظر انسان را به شواهد قابل‌اندازه‌گیری و به خط کد تبدیل می‌کند، و ایرادهایی را که انسان ندیده هم خودش اضافه می‌کند.

## ۲. جریان کلی

</div>

```text
 CAPTURE (local)                 ANALYZE (offline, re-runnable)          ACT
 ─────────────────               ──────────────────────────────          ─────────────────
 mic → audio.wav ──┐             speech → words (epoch ms)               briefs/<id>.md
 recorder.js ──────┼─ events ──▶ fusion: deictic word ↔ pointer  ──▶     → diamond-fix agent
  pointer/hover/dwell/click      analyzers (deterministic, 0 tokens)     → PR + proof
  inventory per page             locate: element → file:line             pqe-findings.json
  LoAF/CLS/event timing          cross-link voice ↔ measurement          regression tests → PQE
 screenshots on dwell/click      report.md (Persian)
```

## ۳. تصمیم‌های کلیدی (با دلیل)

| تصمیم | گزینه‌های رد شده | دلیل |
|---|---|---|
| مرورگر کنترل‌شده با Playwright | افزونه‌ی کروم، اپ دسکتاپ | دسترسی کامل به داده‌های کارایی، تزریق قبل از اسکریپت صفحه، تکرارپذیری. افزونه در فاز بعد |
| ضبط صدا بیرون از صفحه | گرفتن میکروفون داخل صفحه | اپ تحت تست دست نمی‌خورد و مجوز میکروفون صفحه لازم نیست |
| یک ساعت مشترک (میلی‌ثانیه‌ی epoch) | ساعت جدا و هم‌گام‌سازی بعدی | هم‌ترازی ساده و قابل‌آزمون |
| گفتار به متن محلی MLX روی مک | فقط ابری | حریم خصوصی، بدون ریسک تحریم و قطعی، سریع روی تراشه‌ی اپل. ابری به‌عنوان جایگزین |
| تحلیل پس از جلسه | تحلیل زنده | دقت بیشتر، تکرارپذیر، صفر هزینه‌ی توکن. نسخه‌ی زنده در نقشه‌ی راه |
| تحلیلگرهای قطعی، مدل فقط اختیاری | همه‌چیز با مدل | ارزان، قابل‌آزمون، بدون توهم. نقد بصری مدل فقط مشورتی و حداکثر SEV2 |
| پلاگین زمان ساخت برای ریشه‌یابی | فقط اطلاعات داخلی React | React 19 اطلاعات منبع را حذف کرده؛ پلاگین مستقل از فریم‌ورک است |
| موتور خودش کد را تغییر نمی‌دهد | اصلاح خودکار مستقیم | امنیت؛ اصلاح با ایجنت و درخواست ادغام و اثبات انجام می‌شود |
| پایتون | تایپ‌اسکریپت | هم‌زبان با PQE برای هسته‌ی مشترک، و کتابخانه‌های گفتار به متن پایتونی‌اند |

## ۴. مسیریابی مدل‌ها (مدیریت توکن)

| کار | رده | مدل پیش‌فرض |
|---|---|---|
| تمیز کردن متن گفتار، دسته‌بندی | سبک | Haiku |
| نقد بصری، ریشه‌یابی تک‌فایلی، پیاده‌سازی اصلاح | استاندارد | Sonnet |
| ریشه‌یابی چندفایلی، بازبینی معماری | سنگین | Opus |
| یکدستی، کارایی، دسترس‌پذیری، راست‌به‌چپ، معماری ایستا | بدون مدل | — |

قاعده‌ی انتخاب در کد: اگر منبع با اطمینان بالا (۰.۸ به بالا) پیدا شده باشد، رده‌ی استاندارد؛ اگر چند فایل درگیرند یا منبع حدسی است، رده‌ی سنگین؛ ایرادهای معماری همیشه سنگین. بریف هر ایراد فقط همان ایراد و شواهدش را دارد، نه کل جلسه.

## ۵. اسکیل‌هایی که از این موتور جدا می‌شوند

هر بسته ورودی و خروجی مشخص دارد و بدون بقیه قابل استفاده است:

</div>

```text
capture/           diamond-capture        browser + mic recorder, one clock
speech/            diamond-speech-fa      Persian UI-review STT + lexicon
fusion/            diamond-deixis         "this button" → element
analyzers/*        diamond-design-lint    consistency / a11y / rtl / perf / animation
locate/            diamond-locate         DOM element → file:line
fix/ + skills/     diamond-fix            brief → agent → PR with proof
report/pqe_export  pqe-bridge             findings → PQE + regression tests
```

## ۶. ارزیابی گفتار (باید روی صدای خودت اندازه‌گیری شود)

دقت تشخیص گفتار فارسی محاوره‌ای که اصطلاحات انگلیسی دارد فرض نمی‌شود. روش ارزیابی پیشنهادی: ۱۰ دقیقه روایت واقعی ضبط شود، متن درست دستی نوشته شود، نرخ خطای کلمه برای MLX، faster-whisper و ابری مقایسه شود، و واژه‌نامه‌ی اصطلاحات در تنظیمات پروژه بر اساس خطاها کامل شود.

## ۷. نقشه‌ی راه

| فاز | محتوا |
|---|---|
| ۱ (همین نسخه) | ضبط، گفتار به متن، هم‌ترازی، ۱۰ تحلیلگر، ریشه‌یابی، گزارش، خروجی PQE، MCP |
| ۲ | زیرنویس زنده و دستورهای صوتی در حین جلسه، افزونه‌ی کروم برای مرورگر شخصی |
| ۳ | اجرای دوباره‌ی خودکار جلسه در موبایل، تبلت، حالت تاریک و شبکه‌ی کند؛ مقایسه‌ی تصویری قبل و بعد اصلاح |
| ۴ | حلقه‌ی بسته: اصلاح، اجرای دوباره، تأیید خودکار؛ ورود ایرادها به Issues گیت‌هاب و نوشن |
| ۵ | اپ موبایل در شبیه‌ساز (Appium / XCUITest) با همان لایه‌های تحلیل |

## ۸. ریسک‌ها

| ریسک | کنترل |
|---|---|
| خطای تشخیص گفتار فارسی | واژه‌نامه‌ی دامنه، ارزیابی روی صدای واقعی، متن قابل ویرایش قبل از تحلیل |
| اشاره‌ی مبهم | درجه‌ی اطمینان روی هر ایراد؛ اسکرین‌شات لحظه؛ علامت دستی |
| ریشه‌یابی حدسی | روش و اطمینان صریح؛ ایجنت موظف به تأیید قبل از ویرایش |
| اصلاح خراب‌کننده | فقط درخواست ادغام؛ تست‌های بازگشتی و PQE؛ ممنوعیت ویرایش تست‌ها |
| حریم خصوصی صدا | پردازش محلی پیش‌فرض؛ پوشه‌ی جلسات در gitignore |

## ۹. انتقال به ریپوی مستقل

همه‌چیز داخل پوشه‌ی diamond است، به‌جز یک فایل گردش‌کار CI. انتقال با حفظ تاریخچه:

</div>

```bash
git subtree split --prefix=diamond -b diamond-standalone
```

```bash
git push git@github.com:hypermindedd/<new-repo>.git diamond-standalone:main
```

<div dir="rtl">

بعد فایل گردش‌کار CI مربوط به Diamond را به پوشه‌ی گردش‌کار ریپوی جدید منتقل کن و مسیرهای داخلش را از diamond به ریشه تغییر بده.
