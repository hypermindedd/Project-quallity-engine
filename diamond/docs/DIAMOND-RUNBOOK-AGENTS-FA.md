# دستورالعمل اجرای موتور Diamond — برای چیف، کدکس، هرمتیکو و فوررانر

نسخه‌ی موتور: 0.1.2 (کامیت 4687fde) · به‌روزرسانی: ۲۸ آبان ۱۴۰۵

Diamond بازبینی صوتی و تصویری محصول در حال ساخت است. مالک یا بازبین حرف می‌زند و با ماوس اشاره می‌کند. موتور صدا، اشاره، کلیک‌ها و رفتار صفحه را ضبط می‌کند، ایرادها را پیدا می‌کند و تا فایل و خط کد دنبال می‌کند. خروجی شامل گزارش فارسی و یک بریف اصلاح برای هر ایراد است.

---

## ۱. قانون اصلی برای همه‌ی نقش‌ها

Diamond **فقط روی مک مالک** اجرا می‌شود، چون مرورگر و میکروفون آنجاست.

* **نقشی که شل روی مک دارد** (Codex، Claude Code، Claude دسکتاپ، یا ترمینال): خودش اجرا می‌کند.
* **نقشی که فقط چت است** (ChatGPT وب یا اپ، یا هر چت بدون دسترسی به مک): نمی‌تواند اجرا کند. یا دستور را به مالک یا به نقش اجراکننده می‌سپارد، یا فقط خروجی جلسه را تحلیل می‌کند.
* **هیچ نقشی اجازه ندارد** نتیجه‌ی بررسی اجرانشده یا «رد شده» را «قبول» گزارش کند.

---

## ۲. پیش‌نیازها

روی مک فعلی همه نصب و تأیید شده‌اند:

| چیز | محل یا وضعیت |
|---|---|
| راه‌انداز | `~/.local/bin/diamond-run` |
| موتور و محیط پایتون | `~/.diamond-engine` |
| مدل گفتار فارسی (۱.۶ گیگ، محلی) | `~/.diamond-engine/models/large-v3-turbo` |
| مرورگر | Google Chrome نصب‌شده (دانلود جداگانه لازم نیست) |
| مجوز میکروفون | برنامه‌ی Terminal |

**نصب روی یک مک جدید** (فقط یک بار):

۱. از پوشه‌ی Diamondengine در درایو، فایل `diamond-run` و جدیدترین فایل `Diamondengine-src-*.zip` را در پوشه‌ی زیر بگذارید:

```text
~/Downloads/Diamondengine/
```

۲. نصب دائمی راه‌انداز:

```bash
bash ~/Downloads/Diamondengine/diamond-run --install-self
```

۳. اضافه کردن به مسیر جستجوی ترمینال:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

۴. اگر دانلود مدل گفتار از Hugging Face کند بود، دانلود موازی و قابل ادامه:

```bash
~/.diamond-engine/venv/bin/diamond fetch-model --connections 24
```

بار اول که موتور اجرا شود، خودش نصب می‌شود. اگر بعداً فایل zip جدیدتری در درایو باشد، خودش به‌روز می‌شود.

---

## ۳. دستورها (از پوشه‌ی ریشه‌ی پروژه)

**بررسی قبل از اجرا** (هیچ چیزی را تغییر نمی‌دهد):

```bash
diamond-run --doctor
```

**بازبینی صوتی با حضور مالک:** کروم باز می‌شود. مالک حرف می‌زند و اشاره می‌کند، و با بستن پنجره‌ی کروم جلسه تمام می‌شود.

```bash
diamond-run
```

**بررسی خودکار بدون انسان:** بدون پنجره و بدون میکروفون، مدت به ثانیه.

```bash
diamond-run --smoke 20
```

**تحلیل دوباره‌ی آخرین جلسه:**

```bash
diamond-run --analyze-last
```

**اگر تشخیص خودکار سرور پروژه شکست خورد:**

```bash
diamond-run --url http://localhost:3000
```

راه‌انداز این پروژه‌ها را خودش تشخیص می‌دهد و روشن و خاموش می‌کند: Next، Vite، Nuxt، Astro، SvelteKit، CRA، Angular، Gatsby، Remix، FastAPI، Flask، Django و HTML ساده.

**خروجی‌ها:** در پوشه‌ی زیر داخل پروژه.

```text
.diamond/sessions/<جدیدترین>/
  report.md                     گزارش فارسی
  findings.json                 همه‌ی ایرادها با شواهد و فایل‌های کد مرتبط
  briefs/<id>.md                بریف اصلاح هر ایراد
  pqe-findings.json             خروجی برای موتور تست PQE
  test_diamond_regressions.py   تست‌های بازگشتی
  shots/                        اسکرین‌شات‌ها
```

## ۴. چیف

بر اساس ماتریس اختیارات: چیف کدنویسی و هماهنگی می‌کند و حکم نهایی انتشار با اوست.

| مرحله | کار چیف |
|---|---|
| قبل از هر درخواست ادغام رابط کاربری | بررسی خودکار با دستور `diamond-run --smoke 20` روی شاخه، و گذاشتن گزارش در شواهد |
| بعد از بازبینی صوتی مالک | خواندن فایل `findings.json` و تقسیم ایرادها بین خودش و هرمتیکو |
| اصلاح | فقط طبق بریف هر ایراد: اول ریشه را در کد تأیید کند، در ریشه اصلاح کند، تست‌ها را ویرایش نکند |
| قبل از حکم انتشار | اجرای دوباره‌ی Diamond و PQE روی همان SHA. نتیجه‌ی **GO** از PQE لازم است |

**اگر چیف در ChatGPT به‌صورت چت اجرا می‌شود:** دسترسی به مک ندارد. دستور را به مالک یا هرمتیکو یا کدکس بسپارد، و پوشه‌ی جلسه یا فایل `findings.json` را برای تحلیل بگیرد.

## ۵. کدکس (Codex CLI روی مک)

دستورالعمل دائمی Diamond در این فایل نصب شده است، پس جمله‌ی «موتور دایموند رو اجرا کن» را می‌فهمد:

```text
~/.codex/AGENTS.md
```

موتور به شبکه، نوشتن در پوشه‌ی خانه و باز کردن برنامه‌ها نیاز دارد، پس کدکس باید **با دسترسی کامل** اجرا شود.

**حالت تعاملی:**

```bash
codex --sandbox danger-full-access
```

**یک‌خطی بدون تعامل:**

```bash
codex exec --dangerously-bypass-approvals-and-sandbox "موتور دایموند رو روی همین پروژه اجرا کن، حالت خودکار ۲۰ ثانیه‌ای، و نتیجه رو فارسی خلاصه کن"
```

⚠️ **مسیر کدکس هنوز تست نشده است.** سهمیه‌ی حساب تا ۲ آذر تمام شده بود. اولین اجرا را با حالت بررسی قبل از اجرا (`--doctor`) شروع کنید.

**بازبینی صوتی از طریق کدکس:** راه‌انداز خودش یک پنجره‌ی Terminal باز می‌کند، چون مجوز میکروفون فقط به Terminal داده شده. بار اول macOS ممکن است بپرسد که آیا برنامه‌ی اجراکننده می‌تواند Terminal را کنترل کند؛ باید **اجازه** داده شود.

## ۶. هرمتیکو

بر اساس ماتریس اختیارات: هرمتیکو کدنویسی می‌کند و نسخه‌ی مجاز را به نمایندگی مالک منتشر می‌کند.

| مرحله | کار هرمتیکو |
|---|---|
| بعد از هر اصلاح | بررسی خودکار با دستور `diamond-run --smoke 20` و مقایسه با جلسه‌ی قبل: هیچ ایراد شدید یا متوسط جدیدی نباید ایجاد شده باشد |
| ایرادی که خودش ساخته | باید در گزارش بیاید، حتی اگر بعداً اصلاح شده باشد |
| انتشار | فقط برای SHA ای که حکم قطعی چیف یا قفل مالک دارد. گزارش Diamond و PQE همان SHA ضمیمه شود |

**اگر هرمتیکو به مک دسترسی ندارد:** مثل چیف عمل کند؛ دستور را بسپارد و فقط خروجی را تحلیل کند.

---

## ۷. فوررانر

⚠️ در اسناد موجود روی مک، تعریفی از نقش فوررانر پیدا نشد. تا وقتی نقشش مشخص شود، این قواعد برایش برقرار است:

* **اگر شل روی مک دارد:** همان دستورهای بخش ۳. برای کارهای پیش‌رو و اکتشافی (مثل بررسی سریع یک پروژه‌ی تازه) معمولاً بررسی خودکار کافی است:

```bash
diamond-run --smoke 20
```

* **اگر فقط چت است:** فقط تحلیل خروجی‌ها، بدون اجرا.
* **بدون حکم چیف یا قفل مالک** حق انتشار ندارد.

---

## ۸. قالب گزارش (برای همه‌ی نقش‌ها)

۱. **شناسه‌ها:** شناسه‌ی جلسه، SHA پروژه، و کامیت موتور.

۲. **شمارش ایرادها** بر اساس شدت.

۳. **ایرادهای صوتی مالک اول:** هر کدام با عین جمله‌ی مالک و فایل کد مرتبطش.

۴. **ایرادهای خودکار.**

۵. **بررسی‌هایی که اجرا نشده‌اند**، با دلیل. این‌ها هرگز «قبول» حساب نمی‌شوند.

۶. **قاعده‌ی نوشتار:** مسیرها و دستورها هر کدام در یک بلوک کد جدا، نه وسط جمله‌ی فارسی.

---

## ۹. اجرای PQE بعد از اصلاح

اصلاحات PQE فعلاً در شاخه‌ی `pqe/fastapi-ui-detection` هستند و هنوز با شاخه‌ی اصلی ادغام نشده‌اند. اجرا روی مک:

```bash
export PATH="$HOME/.pqe-venv/bin:$PATH" PQE_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

```bash
pqe auto . --no-ai --fail-on never --out /tmp/pqe-run
```

## ۱۰. رفع اشکال

| نشانه | علت | راه حل |
|---|---|---|
| ترمینال پیغام «command not found» می‌دهد | مسیر جستجوی ترمینال تنظیم نیست | دستور بخش ۲، قدم ۳ |
| گزارش می‌گوید میکروفون فقط سکوت ضبط کرد | برنامه‌ی اجراکننده مجوز میکروفون ندارد | از ترمینال اجرا شود، یا تنظیمات Privacy مک، بخش Microphone، گزینه‌ی Terminal روشن شود |
| کد خروج ۳ | پیش‌نیاز کم است | خود پیغام می‌گوید چه چیزی نصب شود (مثلاً پایتون ۳.۱۱ به بالا) |
| کد خروج ۴ | موتور پیدا نشد | فایل zip را در پوشه‌ی دانلودها بگذارید (بخش ۲) |
| کد خروج ۵ | سرور پروژه روشن نشد | گزینه‌ی `--url` را بدهید |
| تبدیل گفتار به متن گیر می‌کند | دانلود مدل از Hugging Face کند است | دستور دانلود موازی مدل (بخش ۲، قدم ۴) |
