## Findings
**P0 — release signal ambiguity:** Sample project logs report `CONDITIONAL` while reusable GitHub workflow is green because self-test explicitly passes `fail-on: never`. Introduce distinct machine-readable `CI_EXECUTION_STATUS` versus `PROJECT_RELEASE_DECISION`; protect deployments from using green workflow alone as GO.
**P0 — coverage guard:** `analysis/triage.py::decide` has no blanket minimum coverage / skipped-check fail-closed policy; SKIPPED, UNCALIBRATED and NOT_COVERED may not prevent GO when no blocking findings/hard goals exist. Add project-approved coverage floors and adversarial regression tests; do not self-approve thresholds.
**P1 — workflow supply chain:** Reusable workflows and actions refer to `@main` rather than immutable pin; require pinned release SHA/tag and upgrade strategy. Inspect action version lifecycle warnings and dependencies.
**P1 — platform proof gap:** Latest self-tests only exercise web/API; no proven Android, iOS or MQL5 production acceptance. Schedule separate environment evidence.
**P1 — integration governance:** Notion reporting creates pages when configured; keep reporting scoped to project owner and do not treat Notion as canonical source.
**P2 — partial failures:** 2 of 12 listed historical runs had failed engine CI before subsequent successful commits. Retain run history and regression linkage.
